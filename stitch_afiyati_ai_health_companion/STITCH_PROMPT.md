# Prompt for Stitch — Afiyati

صمّم واجهة ويب احترافية لتطبيق صحي اسمه **عافيتي / Afiyati**. اللغة الافتراضية عربية RTL، مع زر واضح للتبديل إلى الإنجليزية LTR. يجب أن تكون الواجهة مطمئنة وحديثة وسهلة على الهاتف، وتعتمد أسلوب **premium glassmorphism**: خلفية فاتحة فيها تدرجات تركواز ونعناع، بطاقات زجاجية شفافة، حدود بيضاء ناعمة، ظلال خفيفة، وحركات انتقال هادئة. لا تستخدم صور مرضى أو عناصر تخيف المستخدم.

## تعليمات الدمج الإلزامية

- يوجد مجلد جديد اسمه **`Front`** في جذر المشروع. اعتبره المرجع البصري الجديد والوحيد للواجهة: `Front/_9` للـLanding، `Front/_2` للـDashboard، `Front/77` للشات، `Front/_6` للـOnboarding، `Front/_7` للأدوية، `Front/_5` للمصادر، و`Front/_4` للطوارئ. استخدم `Front/afiyati/DESIGN.md` كمرجع للألوان والخطوط والحركة.
- ملفات `Front` الحالية هي تصدير HTML وصور مرجعية، **وليست تطبيقاً جاهزاً**. حوّل التصميم إلى مكوّنات React نظيفة داخل مشروع التشغيل `stitch_afiyati_ai_health_companion/src`؛ لا تستخدم Tailwind CDN أو صور avatars خارجية أو روابط `#` وهمية في المنتج.
- اربط كل شاشة بالـBackend الحقيقي على `http://127.0.0.1:8000/api` عبر طبقة API موحّدة، واحفظ JWT محلياً كما هو. لا تكتب بيانات وهمية إذا كان Endpoint حقيقياً متاحاً.
- لا تحذف الواجهة القديمة دفعة واحدة. ابنِ الواجهة الجديدة، انقل إليها كل المسارات والـAPI والسلوك، ثم شغّل اختبارات القبول. **بعد نجاح الاختبارات فقط** احذف المكوّنات والـCSS القديمة التي أصبحت غير مستخدمة. لا تحذف Backend أو قاعدة بيانات أو بيانات مستخدمين أو ملفات `Front` المرجعية.
- لا تترك أزراراً شكلية: كل زر تنقل، إرسال، مصادر، جرعة، تصوير وجبة، أو طوارئ يجب أن يؤدي إلى سلوك حقيقي أو حالة Disabled مفسّرة بوضوح.

### عقود الـAPI المطلوب توصيلها

- Auth: `POST /auth/register`، `POST /auth/login`، `GET /auth/me`، `POST /auth/logout`.
- Profile: `GET /profile` و`PUT /profile`. الحالات المدعومة فقط `hypertension` و`type_2_diabetes`.
- Chat: `POST /chat` مع `mode: chat | food | meal | habit`، و`GET /chat/history`. اعرض الرد والمصادر والـTop-K فقط عند طلب المستخدم.
- Symptoms: `POST /symptoms` و`GET /symptoms/history`. إذا كان `emergency: true` انتقل فوراً إلى `/emergency`.
- Food: `POST /meals/detect` ثم تأكيد المكونات والكميات عبر `POST /chat` بوضع `meal` أو `food`، مع `GET /foods/history` و`GET /foods/sources`.
- Medications: `GET/POST /medications`، `PUT/DELETE /medications/:id`، `GET /medications/schedule/today`، `POST /medications/:id/dose`، `GET /medications/reminders/upcoming`.
- Sources: `GET /sources` و`GET /rag/status`. لا تعرض للمستخدم العادي درجات relevance أو نسب ثقة داخلية.

### اختبارات القبول قبل حذف الواجهة القديمة

نفّذ هذه الاختبارات على الواجهة الحقيقية وسجّل النتيجة، مع الحفاظ على إجابات آمنة ومنطقية:

1. **«هل المشي مفيد لضغط الدم؟»** → إجابة مباشرة مرتبطة بالمصادر الطبية، دون تشخيص أو تعديل علاج.
2. **«200 جم موز» في شات الأكل** → قيم لكمية 200 جم مع مصدر رسمي وزر للمصادر؛ الأثر الصحي يراعي الضغط/السكري المسجل.
3. **«هل القهوة مناسبة لحالتي؟»** → يطلب أو يستخدم الكمية عند الحاجة ويعرض المصدر الطبي، ولا يخترع أرقاماً غذائية.
4. **«حاسس بدوخة بعد الغداء» في الشات العام** → يتحول إلى متابعة الأعراض، يحفظ التسجيل ويظهر في السجل.
5. **«حاسس بالاختناق ومش قادر أخد نفسي»** → انتقال فوري إلى شاشة الطوارئ، بدون انتظار نموذج أو إنشاء إجابة عادية.
6. **«هل القهوة مناسبة مع الربو؟»** → يوضح باحترام أن نطاق التطبيق الحالي ضغط الدم والسكري من النوع الثاني فقط.
7. بعد إجابة موثقة، **«ما المصدر؟»** → يعرض نفس المصادر المباشرة للإجابة السابقة.
8. تصوير وجبة → لا يحلل صحياً قبل تأكيد المستخدم للمكوّنات والكميات؛ تظهر حالة الاكتشاف ثم التعديل ثم التحليل.
9. جرعة دواء قادمة → تظهر على Dashboard، وتسجل «تم أخذ الجرعة» أو «تخطي» في السجل دون اقتراح تغيير جرعة.
10. جرّب Desktop وMobile وArabic/English، وتأكد من عدم وجود Console errors أو أزرار غير عاملة أو بيانات مستخدم مفقودة.

## الهوية والبداية

- صمّم Logo بسيطاً يدمج قلباً مع علامة طبية/نبض، واستخدم الاسم «عافيتي» مع سطر صغير: «رفيقة صحتك اليومية».
- أنشئ Landing page فيها Navbar: الشعار، لماذا عافيتي، المصادر الطبية، عربي/English، دخول، وابدأ الآن.
- Hero واضح يشرح القيمة: «صحتك اليومية... بقرارات أوضح». اشرح أن عافيتي يساعد المستخدم على فهم الطعام والعادات ومتابعة الأعراض مع إظهار المصادر، ولا يحل محل الطبيب.
- أضف CTA رئيسي «ابدأ الآن»، CTA ثانوي «كيف يعمل؟»، ورابط طوارئ ظاهر لكن غير مزعج.
- أضف 3 بطاقات فوائد: إجابات مرتبطة بمصادر طبية، تخصيص حسب الملف الصحي، ومصادر يمكن فتحها مباشرة.

## رحلة الاستخدام

- بعد البدء، اعرض Onboarding بسيطاً بالترتيب: الاسم، العمر، الطول، الوزن، الجنس، الحالات المزمنة إن وجدت، ثم الحساسية إن وجدت.
- الحالات المدعومة والقابلة للاختيار فقط: **ارتفاع ضغط الدم** و**السكري من النوع الثاني**. أظهر باقي الحالات Disabled وبجوارها Soon.
- اجعل لوحة المتابعة ترحب بالمستخدم باسمه وتعرض اختصارات كبيرة لـ: شات عافيتي، شات الأكل، متابعة الأعراض، **صوّر وجبتك**، سجل الطعام، الأدوية، والمصادر.
- أظهر بطاقتين واضحتين دائماً في أعلى لوحة المتابعة: «جرعتك التالية» مع الوقت وإجراءات «تم أخذ الجرعة / تخطي»، و«صوّر وجبتك» لبدء التحليل بالكاميرا.

## الشات الذكي

أنشئ شاشة شات رئيسية فيها 3 تبويبات واضحة:

1. **شات عافيتي**: سؤال صحي أو متابعة كلام سابق، مع تذكير صغير بأن الإجابات تثقيفية ومتصلة بالملف الصحي.
2. **شات الأكل**: حقل لاسم طعام أو مشروب وحقل اختياري للكمية بالجرام. اعرض لاحقاً القيم الغذائية من مصدر رسمي، وتأثير الطعام لكل من الضغط أو السكري، ثم أزرار «المصادر الطبية» و«Top-K».
3. **متابعة الأعراض**: حقل لوصف العرض، Slider للشدة من 1 إلى 10، وبطاقة تعرض آخر متابعات الأعراض وتاريخها وشدتها. اشرح أن هذه متابعة وليست تشخيصاً.

استخدم أمثلة جاهزة داخل كل تبويب. اجعل زر الإرسال دائرياً وواضحاً، مع حالات Loading جميلة مثل: «أبحث في المصادر»، «أتحقق من بيانات الطعام»، «أجهز إجابة موثقة».

## تصوير الطعام وتحليل الوجبة

- صمّم صفحة مستقلة باسم **«صوّر وجبتك»** فيها منطقة كبيرة وأنيقة لاختيار صورة أو فتح الكاميرا، مع أيقونة كاميرا واضحة وحالة معاينة للصورة.
- بعد رفع الصورة، اعرض Loading بصري: «أكتشف المكونات المحتملة»، ثم قائمة قابلة للتعديل بالمكونات المكتشفة.
- لا تعامل نتيجة الصورة كحقيقة نهائية: اطلب من المستخدم تأكيد أو تعديل كل مكوّن وإضافة الكمية بالجرام قبل أي تحليل صحي.
- بعد التأكيد، اعرض بيانات الطعام والمشروبات ومصادرها الرسمية، ثم تأثيراً منفصلاً على الضغط أو السكري حسب الملف الصحي.
- أضف زر «حفظ في سجل الطعام» وحالة نجاح بسيطة، مع إمكانية الرجوع إلى سجل الوجبات السابقة والكميات والمصادر.

## الأدوية والتنبيهات

- صمّم صفحة **«أدويتي»** ببطاقات نظيفة لكل دواء: الاسم، الجرعة الموصوفة، وقت/أوقات التذكير، وعلاقته بالطعام إن وجدت.
- أضف نموذج «إضافة دواء» مرتباً: اسم الدواء، الجرعة الموصوفة، عدد المرات، أوقات التذكير، تاريخ البداية/النهاية، وملاحظات.
- اعرض على لوحة المتابعة بطاقة «جرعتك التالية» بشكل بارز مع عدّاد زمني، وزرين كبيرين: «تم أخذ الجرعة» و«تخطي».
- عند فتح التطبيق، اقترح بلطف تفعيل إشعارات المتصفح للتذكير؛ صمّم Permission state واضحة: غير مفعّلة، مفعّلة، أو غير مدعومة.
- صمّم شكل Notification مختصر: «موعد دواء [الاسم] — [الجرعة] الآن»، مع دعوة لفتح عافيتي وتسجيل حالة الجرعة.
- أضف سجل جرعات يوضح تم أخذها / تم تخطيها / فاتت، لكن لا تقترح أبداً تعديل الجرعة أو إيقاف الدواء؛ أظهر تنبيهاً دائماً بأن أي تغيير علاجي يرجع للطبيب أو الصيدلي.

## الطوارئ والسلامة

- إذا كتب المستخدم: «حاسس بالاختناق»، «مش قادر أتنفس»، ألم شديد في الصدر، فقدان وعي، نزيف شديد، تورم اللسان أو الشفاه، ضعف/تنميل مفاجئ أو ثقل كلام، انتقل فوراً إلى Emergency screen ولا تعرض إجابة شات عادية.
- صفحة الطوارئ حمراء وواضحة، فيها عنوان «قد تحتاج إلى مساعدة طبية عاجلة»، زر كبير «اتصل بالإسعاف 123» لمصر، تنبيه لعدم القيادة، ورابط عودة آمن.
- لا تعرض تشخيصاً أو تغييراً لجرعة دواء، ولا تدّعِ أن طعاماً آمن طبياً من غير مصدر.

## المصادر والشفافية

- في كل إجابة، اجعل المصادر في أزرار منفصلة وسهلة الفتح، ولا تعرض نسب ثقة أو درجات تقنية للمستخدم العادي.
- صمّم صفحة مصادر منظمة لبيانات الطعام والمشروبات والمصادر الطبية، وكل مصدر له المؤسسة والرابط الرسمي والاستخدام داخل التطبيق.

## جودة التصميم

- اجعل Arabic typography ممتازة، المسافات مريحة، النصوص قصيرة، والأيقونات من نفس العائلة.
- التصميم Responsive: Sidebar على سطح المكتب وBottom navigation على الهاتف.
- استخدم hover states خفيفة، focus states واضحة، واحترم `prefers-reduced-motion`.
- لا تستخدم Dark mode في هذه النسخة؛ حافظ على تصميم صحي هادئ ومضيء.
